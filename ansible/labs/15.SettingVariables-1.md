# Basic Variable Methods in Ansible (vars, vars_files, host vars, -e)

Lab Objective
In this lab, you’ll learn about variables in Ansible, how to define them in different contexts, and how variable precedence determines which variable takes effect. Each step builds upon the previous one, adding more dinosaurs and amusing (but accurate!) scenarios.

Procedure
Reset the lab tools
Let’s start by resetting the environment to ensure everything is fresh for this lab. Run:

student@bchd:~$ bash ~/px/scripts/full-setup.sh

This resets any changes made in previous labs and gets everything ready for you.

What is a variable?
A variable in Ansible is a way to store and reuse data. Instead of hardcoding values into your playbooks, you define variables that can change based on the environment, host, or context. This makes playbooks more flexible and easier to manage.

Variable Types and Precedence:

Variables can be defined in multiple locations, each with a different priority. Let’s break them down:

Type	Description	Location/Use	Precedence
-e (extra vars)	Variables passed directly on the command line.	ansible-playbook playbook.yml -e "key=value"	Highest
Task Vars	Variables defined within a specific task, taking precedence over other variable types.	Defined directly in the vars field of a task.	High
Play Vars	Variables defined within a play, applying to all tasks in the play.	Defined in the vars section of a play.	Medium
vars_files	Variables imported from external files, useful for managing reusable configurations.	Files specified using the vars_files directive in a playbook.	Medium-Low
Host Vars	Variables defined for a specific host in the inventory file.	Defined in the inventory file after a host name.	Low
Note: For a complete breakdown of Ansible variable precedence, check out the official documentation.

Define variables in the inventory file:
Start with the lowest precedence by defining variables in the inventory file. Remove your original inventory file and open a new one:

student@bchd:~$ rm ~/mycode/inv/dev/* && vim ~/mycode/inv/dev/hosts

Add the following, and note we've added three variables (dino_name, dino_food, and dino_direction):

bender ansible_host=10.10.2.3 ansible_user=bender dino_name=Triceratops dino_food="ferns" dino_direction="to your left"
Save and exit.

Create a playbook that uses these variables to simulate a Jurassic Park jeep tour. The message will be written to /tmp/jurassicpark.txt using the shell module (very simple module, as it is only used to execute shell commands!)

student@bchd:~$ vim ~/jurassic_tour.yaml

- hosts: bender
  tasks:
    - name: Announce the dinosaur
      shell: |
        echo "Our next stop will take us past the {{ dino_name }}. It loves eating {{ dino_food }}.
        You should be able to see it if you look {{ dino_direction }}" >> /tmp/jurassicpark.txt
Execute the playbook and verify the result:

student@bchd:~$ ansible-playbook ~/jurassic_tour.yaml

Use SSH to check the contents of /tmp/jurassicpark.txt:

student@bchd:~$ ssh bender "cat /tmp/jurassicpark.txt"

Our next stop will take us past the Triceratops. It loves eating ferns.
You should be able to see it if you look to your left
Add a play variable
Let’s override the host variables with play-level variables. Edit the playbook:

student@bchd:~$ vim ~/jurassic_tour.yaml

- hosts: bender
  vars:
    dino_name: Velociraptor  # Overrides host variable
    dino_food: "small mammals and lizards"
    dino_direction: "to your right"
  tasks:
    - name: Announce the dinosaur
      shell: |
        echo "Our next stop will take us past the {{ dino_name }}. It loves eating {{ dino_food }}.
        You should be able to see it if you look {{ dino_direction }}" >> /tmp/jurassicpark.txt
Execute the playbook again:

student@bchd:~$ ansible-playbook ~/jurassic_tour.yaml

Check the updated contents of /tmp/jurassicpark.txt:

student@bchd:~$ ssh bender "cat /tmp/jurassicpark.txt"

[OTHER OUTPUT]
Our next stop will take us past the Velociraptor. It loves eating small mammals and lizards.
You should be able to see it if you look to your right
Add a variables file
Create a file to define the variables:

student@bchd:~$ mkdir -p ~/mycode/vars/

student@bchd:~$ vim ~/mycode/vars/dino_vars.yml

Add this content:

dino_name: Stegosaurus
dino_food: "ferns and mosses"
dino_direction: "to your left"
Edit the playbook to include the vars_files directive:

student@bchd:~$ vim ~/jurassic_tour.yaml

Update it like this:

- hosts: bender
  vars_files:
    - ~/mycode/vars/dino_vars.yml
  vars:
    dino_name: Velociraptor  # Overrides host variable
    dino_food: "small mammals and lizards"
    dino_direction: "to your right"
  tasks:
    - name: Announce the dinosaur
      shell: |
        echo "Our next stop will take us past the {{ dino_name }}. It loves eating {{ dino_food }}.
        You should be able to see it if you look {{ dino_direction }}" >> /tmp/jurassicpark.txt
Execute the playbook:

student@bchd:~$ ansible-playbook ~/jurassic_tour.yaml

Check the updated contents of /tmp/jurassicpark.txt:

student@bchd:~$ ssh bender "cat /tmp/jurassicpark.txt"

[OTHER OUTPUT]
Our next stop will take us past the Stegosaurus. It loves eating ferns and mosses.
You should be able to see it if you look to your left
Add a task variable
Let’s override the play variables with task-level variables. Edit the playbook:

student@bchd:~$ vim ~/jurassic_tour.yaml

- hosts: bender
  vars:
    dino_name: Velociraptor  # Overrides host variable
    dino_food: "small mammals and lizards"
    dino_direction: "to your right"
  tasks:
    - name: Announce the dinosaur
      shell: |
        echo "Our next stop will take us past the {{ dino_name }}. It loves eating {{ dino_food }}.
        You should be able to see it if you look {{ dino_direction }}" >> /tmp/jurassicpark.txt
      vars:
        dino_name: Brachiosaurus  # Overrides play variable
        dino_food: "leaves from tall trees"
        dino_direction: "to your right above the tree line"
Execute the playbook again:

student@bchd:~$ ansible-playbook ~/jurassic_tour.yaml

Check the updated contents of /tmp/jurassicpark.txt:

student@bchd:~$ ssh bender "cat /tmp/jurassicpark.txt"

[OTHER OUTPUT]
Our next stop will take us past the Brachiosaurus. It loves eating leaves from tall trees.
You should be able to see it if you look to your right above the tree line
Override with Extra Vars (-e)
Extra vars have the highest precedence. Run the playbook with extra variables, which should override every variable that we've set so far:

student@bchd:~$ ansible-playbook ~/jurassic_tour.yaml -e "dino_name='T-Rex' dino_food='slow Jurassic Park visitors' dino_direction='OH NO IT\'S BEHIND US EVERYONE RUN'"

Check the updated contents of /tmp/jurassicpark.txt:

### SOLUTION
Here’s how to define fav_movie using different Jurassic Park movies for each location, demonstrating variable precedence. You didn't have to do all of these, this is just for reference.

Inventory File
Add the lowest-precedence version of fav_movie to the inventory file:

fry ansible_host=10.10.2.4 ansible_user=fry fav_movie="Jurassic Park"
Variables File
Create a vars_files file with the next version of fav_movie:

# ~/mycode/vars/movies.yml
fav_movie: "Jurassic Park: The Lost World"
Play Variables
Define another version of fav_movie in the playbook itself:

vars:
  fav_movie: "Jurassic Park III"
Task Variables
Add the highest-precedence version of fav_movie to the specific task:

- name: Create directory for favorite movie
  file:
    path: "/tmp/{{ fav_movie }}"
    state: directory
  vars:
    fav_movie: "Jurassic World"
Extra Variables

And yes, you can use -e as well!
