# Understanding and using the loop keywords in Ansible 

Lab Objective
In this lab, you’ll learn what a loop is, why it’s useful, and how to use the loop keyword in Ansible. You’ll see how it simplifies repetitive tasks, handles lists and complex data, and even overcomes limitations in certain modules.

Procedure
Before we dive in, let’s reset everything so we start fresh. Run the following command to ensure the lab tools are in the correct state:

student@bchd:~$ bash ~/px/scripts/full-setup.sh

This command resets any changes from previous labs, so you’re working with a clean slate.

What is a loop, and why does it matter?
A loop in Ansible is a way to perform the same task multiple times, each time using a different value from a list or structure. Without loops, you’d have to manually write out repetitive tasks, which is inefficient and harder to maintain. Let's see this in action.

Let’s start by writing a playbook that uses three separate tasks to print out quotes from Back to the Future.

student@bchd:~$ vim ~/quotes_playbook.yaml

Add the following content:

- hosts: localhost
  tasks:
    - name: Print quote 1
      debug:
        msg: "Roads? Where we're going, we don't need roads."
    - name: Print quote 2
      debug:
        msg: "If my calculations are correct, when this baby hits 88 miles per hour, you're gonna see some serious stuff."
    - name: Print quote 3
      debug:
        msg: "Your future is whatever you make it, so make it a good one."
Save the file and run it:

student@bchd:~$ ansible-playbook ~/quotes_playbook.yaml

Notice how repetitive it is to write out a task for each quote. This works, but it’s not elegant. Let’s simplify it with a loop!

Now let’s update the playbook to replace those three tasks with a single task using a loop.

student@bchd:~$ vim ~/quotes_playbook.yaml

Replace the tasks with:

- hosts: localhost
  tasks:
    - name: Print quotes
      debug:
        msg: "{{ item }}"
      loop:
        - "Roads? Where we're going, we don't need roads."
        - "If my calculations are correct, when this baby hits 88 miles per hour, you're gonna see some serious stuff."
        - "Your future is whatever you make it, so make it a good one."
Run the playbook again:

student@bchd:~$ ansible-playbook ~/quotes_playbook.yaml

Look how much cleaner that is! You’ve accomplished the same thing with less effort. Plus, this makes it super easy to add more quotes.

Mini Challenge: Add "Great Scott!" to the list of quotes in the loop and run the playbook again.

SOLUTION
Understand the item keyword
When using a loop, the item keyword represents the current value being processed in the loop. It’s how you dynamically reference each value. Now that you understand the basics, let’s see how loops handle more complex data.

with_items vs. loop You may have seen in legacy code that instead of loop tasks use with_items. While with_items still works and isn't deprecated (yet) it does lack flexibility that the loop keyword introduced in Ansible 2.5- specifically, being able to loop over dictionaries!

Let's try looping over some more challenging data. Create a playbook to manage user accounts on bender using a loop with dictionaries. Each dictionary contains a user’s name and their shell. The debug is there to show you what the variables item.name and item.shell equate to when you run the playbook!

student@bchd:~$ vim ~/create_users.yaml

Add the following:

- hosts: bender
  become: true

  vars:
    delorean:
      - { name: 'marty', shell: '/bin/bash' }
      - { name: 'doc', shell: '/bin/zsh' }

  tasks:
    - name: Create users
      user:
        name: "{{ item.name }}"   # look at the value of "name" above
        shell: "{{ item.shell }}" # look at the value of "shell" above
        state: present
      loop: "{{ delorean }}"

    - name: Debug user details
      debug:
        msg: "Created user {{ item.name }} with shell {{ item.shell }}"
      loop: "{{ delorean }}"
Run the playbook:

student@bchd:~$ ansible-playbook ~/create_users.yaml

Pay attention to the debug output. It shows how item.name and item.shell are being used during each iteration.

Using lists with modules that accept them
Some modules, like apt, can process lists directly without a loop. Let’s see this in a playbook for fry.

student@bchd:~$ vim ~/install_packages_fry.yaml

Add this:

- hosts: fry
  tasks:
    - name: Install packages
      apt:
        name:
          - sl
          - cmatrix
        state: present
      become: true
Run the playbook:

student@bchd:~$ ansible-playbook ~/install_packages_fry.yaml

The apt module is smart enough to handle a list of packages directly. You can confirm this in the apt module documentation.

Some modules, like user, don’t support lists and will fail if you try to use one. Let’s see this in a playbook for zoidberg.

student@bchd:~$ vim ~/create_users_zoidberg_fail.yaml

Add this:

- hosts: zoidberg
  become: true
  
  tasks:
    - name: Try to create multiple users (incorrect)
      user:
        name:
          - biff
          - george
        state: present
Run the playbook:

student@bchd:~$ ansible-playbook ~/create_users_zoidberg_fail.yaml

The file module expects path to be a single string, not a list. If you want to create multiple directories, read on!

Let’s fix the playbook by using a loop.

student@bchd:~$ vim ~/create_users_zoidberg_succeed.yaml

Update it with:

- hosts: zoidberg
  become: true

  tasks:
    - name: Create multiple users (correct)
      user:
        name: "{{ item }}"
        state: present
      loop:
        - alice
        - bob

Run the playbook again:

student@bchd:~$ ansible-playbook ~/create_users_zoidberg_succeed.yaml

Success! The loop bypasses the limitation of the package module.

Challenge
Looping Over Data
Use the starter playbook below to practice looping over lists and dictionaries. Change the msg parameters to use the data being returned by loop!

- hosts: localhost
  tasks:
    - name: Loop over names
      debug:
        msg: # FIX THIS LINE!
             # Recommended output: "Marty McFly is a classic character!"
             #                     "Doc Brown is a classic character!"
             #                     "Biff Tannen is is a classic character!"
      loop:
        - Marty McFly
        - Doc Brown
        - Biff Tannen

    - name: Loop over items with keys
      debug:
        msg: # FIX THIS LINE!
             # Recommended output: "Marty McFly is known for hoverboards!"
             #                     "Doc Brown is known for DeLoreans!"
             #                     "Biff Tannen is known for manure!"
      loop:
        - { character: "Marty McFly", object: "hoverboards" }
        - { character: "Doc Brown", object: "DeLoreans" }
        - { character: "Biff Tannen", object: "manure" }

## SOLUTION
Update the playbook like this:

- hosts: localhost
  tasks:
    - name: Loop over names
      debug:
        msg: "{{ item }} is a classic character!"
      loop:
        - Marty McFly
        - Doc Brown
        - Biff Tannen

    - name: Loop over items with keys
      debug:
        msg: "{{ item.character }} is known for {{ item.object }}!"
      loop:
        - { character: "Marty McFly", object: "hoverboards" }
        - { character: "Doc Brown", object: "DeLoreans" }
        - { character: "Biff Tannen", object: "manure" }
