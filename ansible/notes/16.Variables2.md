# Advanced Variable Methods in Ansible (vars_prompt, register, set_fact)

Lab Objective
In this lab, we’ll explore some advanced ways to create and manage variables in Ansible. You’ll learn about vars_prompt for getting user input, register for capturing task outputs, and set_fact for defining new variables during execution. Each method is a powerful tool in your Ansible toolbox.

Here’s a quick rundown of the tools we’ll use in this lab and where they sit in Ansible’s variable precedence order. (Hint: knowing precedence is key to avoiding surprises!)

Tool	Description	Precedence
vars_prompt	Prompts the user to input variables during playbook execution.	Medium-Low
register	Captures task output and saves it as a variable for use in later tasks.	Defined during execution
set_fact	Dynamically creates or updates variables during playbook execution.	Medium-High (overrides others in the play)
You can see the full list of variable precedence and where these tools fit in the Ansible documentation.

Procedure
We'll be using the planetexpress team for this lab. Let’s reset everything to make sure we’re starting fresh:

student@bchd:~$ bash ~/px/scripts/full-setup.sh

Ansible has some cool encryption options when prompting for variables, and for that we need passlib. Run:

student@bchd:~$ python3 -m pip install passlib

Explore vars_prompt
Let’s start with vars_prompt, which pauses the playbook to ask for input. This is handy for sensitive or dynamic values. We’ll prompt for a password, but note you could use this for any input you need!

student@bchd:~$ vim ~/mycode/prompt-playbook01.yml

Add this playbook:

---
- name: How to prompt for variables
  hosts: localhost
  gather_facts: no

  vars_prompt:
    - name: "yourpassword"
      prompt: "What is your password?"
      private: yes
      encrypt: "sha512_crypt"
      confirm: yes
      salt_size: 7
      default: "qwerty"

  tasks:
    - name: Print out the password
      debug:
        msg: "{{ yourpassword }}"
Save the file and run the playbook:

student@bchd:~$ ansible-playbook ~/mycode/prompt-playbook01.yml

Enter a password when prompted and see how it’s encrypted in the logs. Pretty neat, right?

Try commenting out optional parameters like default, encrypt, or confirm and see how the behavior changes. Keep experimenting until you’re comfortable with how vars_prompt works.

Use Cases for vars_prompt

Collecting sensitive data like passwords or API keys.
Asking for user input during ad-hoc playbook runs.
Setting dynamic configuration values during execution.
Capturing Output with register
Let’s move on to register. This keyword saves the output of a task as a variable. You can use it later in the playbook to make decisions, display information, or run additional tasks.

student@bchd:~$ vim ~/mycode/register-playbook.yml

Add this playbook:

---
- name: Demonstrate register
  hosts: zoidberg
  tasks:
    - name: Install sl
      apt:
        name: sl
        state: present
        update_cache: yes
      register: apt_result
      become: true

    - name: Display full output
      debug:
        var: apt_result

    - name: Display specific parts of the output
      debug:
        msg: "The task changed: {{ apt_result.changed }}"
Save and run the playbook:

student@bchd:~$ ansible-playbook ~/mycode/register-playbook.yml

Check out the output. The first debug task shows everything register captured, while the second displays specific pieces of the data. Predictable output like this is detailed in the apt module documentation.

Use Cases for register

Capturing command output for use in later tasks.
Checking whether a task made changes and acting conditionally.
Debugging or logging detailed task results.
Define Variables Dynamically with set_fact
The set_fact module lets you create or update variables during playbook execution. Let’s use it to get the current date and create a directory with that name.

student@bchd:~$ vim ~/mycode/set_fact-playbook.yml

Add this playbook:

---
- name: Demonstrate set_fact
  hosts: localhost
  tasks:
    - name: Get the current date
      command: date +"%Y-%m-%d"
      register: result

    - name: Set a fact for the current date
      set_fact:
        date_now: "{{ result.stdout }}"

    - name: Create a directory with the current date
      file:
        path: "/tmp/newdir-{{ date_now }}"
        state: directory

    - name: Display the fact
      debug:
        msg: "Directory created with name: /tmp/newdir-{{ date_now }}"
Save and run the playbook:

student@bchd:~$ ansible-playbook ~/mycode/set_fact-playbook.yml

Check /tmp for the new directory. It’ll have today’s date as its name. Cool, right?

student@bchd:~$ ls /tmp

Use Cases for set_fact

Defining variables dynamically based on task outputs.
Simplifying complex playbooks by creating reusable variables.
Adjusting variables dynamically during execution, such as creating temporary paths or conditional settings.

SOLUTION
Here is the completed playbook:

---
- name: How to prompt for variables
  hosts: professors     # connect to the professors group
  gather_facts: no

  vars_prompt:
    - name: "ansible_ssh_pass"  # password to connect to the hosts in the professors group
      prompt: "What is your ssh password?"  # Question to ask
      private: yes  # Do not display input
      confirm: yes  # Require confirmation
Explanation:

private: yes: Ensures the password input is hidden as the user types it.
confirm: yes: Requires the user to re-enter the password to confirm their input.
